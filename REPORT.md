# Лабораторная работа №3: Линейные модели

## 1. Данные и подготовка

### Student_Performance.csv (линейная регрессия)
- **Объём:** ~10000 строк, 5 признаков
- **Целевая переменная:** `Performance Index` (непрерывная, шкала 0–100)
- **Предобработка:**
  - Признак `Extracurricular Activities` (Yes/No) закодирован как бинарный: Yes - 1, No - 0
  - Остальные признаки (`Hours Studied`, `Previous Scores`, `Sleep Hours`, `Sample Question Papers Practiced`) уже числовые
  - Пропусков в данных не обнаружено
- **Масштабирование:** StandardScaler (приведение к нулевому среднему и единичной дисперсии). Fit выполняется только на train-части, чтобы избежать data leakage
- **Разбиение:** train/test = 80/20, `random_state=42`

### german.csv (логистическая регрессия)
- **Объём:** 1000 строк, 20 признаков
- **Целевая переменная:** `Creditability` (0/1) — находится в первом столбце
- **Предобработка:**
  - Все признаки уже представлены в числовом виде (категориальные закодированы целыми числами от 1 до N)
  - Пропусков нет
- **Масштабирование:** StandardScaler (критично для градиентного спуска и KNN)
- **Разбиение:** train/test = 80/20, `random_state=42`

## 2. Гипотезы и эксперименты

### Линейная регрессия
- **Гипотеза:** Performance Index линейно зависит от количества часов учёбы, предыдущих оценок, сна и решённых вариантов
- **Параметры обучения:** learning_rate = 0.05, epochs = 800, инициализация весов нулями
- **Функция потерь:** MSE 
- **Наблюдение:** MSE монотонно убывает на протяжении всех 800 эпох, сходимость стабильная благодаря масштабированию признаков

### Логистическая регрессия
- **Гипотеза:** кредитоспособность (`Creditability`) линейно разделима в пространстве признаков после масштабирования
- **Параметры обучения:** learning_rate = 0.1, epochs = 1000, инициализация весов нулями
- **Функция потерь:** Binary Cross-Entropy 
- **Порог классификации:** 0.5
- **Наблюдение:** BCE стабилизируется, модель обучается без расходимости

### Сравнение моделей
- **Ожидалось:** Decision Tree даст высокую точность на train, но может переобучиться; KNN чувствителен к выбору k и шуму; логистическая регрессия — устойчивый бейзлайн
- **Эксперимент:** все три модели обучались на одном и том же разбиении данных (80/20, random_state=42) с одинаковым масштабированием

## 4. Выводы

### Линейная регрессия
- Собственная реализация с пакетным градиентным спуском успешно обучается и даёт MSE = 4.0826 на тестовой выборке
- Масштабирование признаков через StandardScaler критично — без него градиентный спуск сходился бы медленно или расходился из-за разного масштаба признаков (например, `Previous Scores` ~50–100, а `Sample Question Papers Practiced` ~0–9)
- Ошибка ~2 балла по 100-балльной шкале приемлемa для линейной модели

### Сравнение классификаторов
- **Собственная логистическая регрессия победила** по ROC-AUC (0.792), Recall (0.891) и F1 (0.834) — лучший общий результат
- **Decision Tree выиграл по Precision (0.839)** — когда дерево предсказывает «кредитоспособен», оно почти всегда право, но пропускает много положительных случаев (recall 0.754). Это типичное поведение деревьев — они стремятся к «чистым» листьям
- **KNN показал средние результаты** — стабильные по всем метрикам, но без явных преимуществ. Чувствителен к выбору k и локальной структуре данных
- **Почему логистическая регрессия лучше по ROC-AUC:** она выдаёт хорошо откалиброванные вероятности, в то время как дерево и KNN дают менее гладкие decision boundary
- **Практический смысл:** в банковской задаче высокий recall (0.89) у нашей модели означает, что мы находим больше кредитоспособных клиентов — это напрямую влияет на прибыль банка

### Итог
Собственная реализация логистической регрессии с пакетным градиентным спуском показала **лучший сбалансированный результат** (F1 = 0.834) среди трёх моделей, подтверждая эффективность метода для линейно разделимых задач.

- **Фиксированный `random_state=42`** для train/test split во всех экспериментах

- **Инициализация весов нулями** в обеих собственных моделях — полностью детерминированная
- **Параметры обучения зафиксированы:** lr=0.05/epochs=800 для регрессии, lr=0.1/epochs=1000 для классификации
- **Результаты экспериментов** сохранены в `experiment_results.json` для автоматической сверки
